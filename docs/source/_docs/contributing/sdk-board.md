# SDK 与板级适配

平台以 SiFli SDK 的 v2.5 系列为开发基础，使用项目自己的板级目录和 ACPU 计算组件。SDK 独立 EPD 板级支持、通用字体修复和软件混音修复分别送审，不能把送审状态当成已经合入官方分支。

本地 SDK 另外存在独立板目录、支持板索引、TLS 证书生成文件和编辑器文件的未提交变化。它们不自动属于字体或音频评审，也不因文档记录而成为正式基线的一部分。

## 字体修复的内容与接口影响

TinyTTF 修复文件读取、定位和分配失败的传播；创建失败时关闭来源并清理对象；调整字号时清除旧尺寸相关缓存；无效或未完成字形不进入有效缓存。修复保留正常字体的尺寸、字宽与像素行为，文件和内存两类来源都参与回归。

公开函数调用方式保持兼容。可选错误处理及资源预算通过默认兼容的宏接入，其他项目无需增加平台专用参数。CFF 支持及默认轮廓能力不被本项目限制替换；本项目在 `compute_reader_font` 中显式设置轮廓预算和支持范围。

## 软件混音修复的内容与接口影响

混音把多个声音转换到输出格式后合成。补丁修正客户端增益、固定硬件增益基准、播放中曲线变化时的正增益与饱和处理，并保留原有零档静音配置、公共静音、私有音量、EQ 调试和蓝牙音量语义。缓存时长按实际进入混音队列的数据格式计算。

公开函数签名保持不变。关闭软件混音时，codec/I2S 两类配置的预处理输出已与对应上游基线比对一致。开启混音时行为得到修正，因此依赖旧错误行为的项目仍需验证输出音量。

当前 SDK 在软件混音开启时强制启用 TWS 混音，不能仅从外部定义 `TWS_MIX_ENABLE=0` 推断最终存在非 TWS A2DP 原始缓存路径。应以实际预处理结果判断构建分支。

本平台尚未完成所有蓝牙播放路径的音量适配验证。恢复通用语义后，不能继续只依赖分类私有音量控制 TWS 输出；只修改 PCM 包装也会遗漏 SDK MP3/WAV 播放路径。这是发布前待处理事项，不是公开接口签名变化。

## 两套板级目录

| 对象 | 路径 | 职责 |
| --- | --- | --- |
| 本项目板型 | `boards/sf32lb57-epd-gyd7n6` | 配合项目显示、触摸、电源、音频与 USB 服务运行；构建名为 `sf32lb57-epd-gyd7n6_hcpu`。 |
| SDK 独立板型 | `SiFli-SDK/customer/boards/sf32lb57-epd_n16r16` | 按 SDK 目录、引脚、初始化、电源和构建惯例描述板子，使用 SDK 原生 E0470A03 选择项。 |

新增 SDK 板级支持的主体是 `customer/boards`，另有中英文支持板列表用于文档发现。板配置定义硬件连接和默认能力，应用负责启用具体业务；平台服务、应用状态机和项目私有驱动不随新增板型一并迁入 SDK。

独立板目录提供 PA 与麦克风供电函数；SDK 通用 PDM 驱动没有为此修改，不能据函数存在就声称所有原生录音流程都会自动调用。该独立板也没有替换本项目构建所用板型。

板级配置、SDK Kconfig 与工程配置共同决定最终 `rtconfig.h`。某个外设未启用时，保存菜单配置可能不保留其依赖项的值；判断实际硬件参数，应检查启用该外设后形成的有效配置，不孤立比较被裁掉的条目。

源码入口：项目板目录（源码：`boards/sf32lb57-epd-gyd7n6/`）、项目板服务（源码：`src/boards/`）、SDK 板目录（源码：`SiFli-SDK/customer/boards/sf32lb57-epd_n16r16/`）、[构建配置](../build/build-configuration.md)。
