# 显示、输入与调度

界面线程拥有 LVGL 页面和控件，后台线程负责产生可供界面消费的结果。墨水屏刷新通过独立的提交和完成状态衔接。用户点击已经被处理、控件已经更新和物理屏幕已经完成刷新，分别发生在不同阶段。

## 一次交互的处理路径

| 环节 | 执行者 | 处理内容 |
| --- | --- | --- |
| 采样 | 触摸、按键驱动及输入适配 | 获取触点或按键状态，形成输入事件。 |
| 分发 | 界面线程、平台输入范围 | 将事件交给最上层有效页面或弹窗。实体电源键由系统电源与锁屏流程处理。 |
| 业务受理 | 页面回调 | 更新内存状态或提交后台请求；回调不等待完整文件读写、网络或文档转换。 |
| 结果应用 | 界面线程 | 检查任务和页面是否仍匹配，更新实际变化的文本、图像或布局。 |
| 绘制提交 | LVGL、刷新协调器 | 合并待刷新内容，按交互及刷新策略提交。 |
| 显示结束 | 显示驱动及完成通知 | 结束本次刷屏，允许后续提交及旧帧回收。 |

后台结果携带任务身份或版本。页面已关闭、书籍已切换、字体配置已变化时，旧结果只用于完成清理，不写回当前页面。阅读算法和屏幕刷新可以各自推进，完成帧的显示仍需遵守显示引用生命周期。

## 页面生命周期与切换

页面 START 创建控件，RESUME 恢复当前状态，PAUSE 暂停页面交互，STOP 删除页面拥有的对象和回调。平台导航负责切换请求和返回关系。页面恢复时复用仍有效的控件，仅刷新变化内容；文件扫描、图像解码和应用服务工作不放在页面恢复回调内完整执行。

页面专用 LVGL 定时器、输入监听和异步结果接收点必须在页面结束时撤销。后台任务有独立的停止和引用协议，退出页面不等于可以立即卸载模块。详见[应用运行与生命周期](application-runtime.md)。

## 局部刷新与全屏刷新

刷新协调器维护刷新请求、提交序号和是否空闲。局部交互可以只更新受影响区域；用户的全刷间隔决定周期清理。进入墙纸的锁定休眠和关机路径请求一次全刷，等待完成后才交出显示及电源资源。

`epd_app_request_full_refresh()` 表示申请全刷，`epd_app_refresh_submission()` 与 `epd_app_refresh_done()` 用于判断提交及完成。不能用函数返回或固定延时代替显示完成确认。按键提示音也有自己的音频开关与任务，不是屏幕刷新完成标志。

## 全局键盘

键盘由应用输入框与平台复合键盘控件协作：输入框持有已提交文字，键盘持有尚未选字的拼音及候选状态。开始拼音输入时，候选条替换键盘工具条；选中候选后才把文字提交到输入框。中英文、数字、符号、语音和收起动作由统一控件处理。

收起键盘保留已经提交的输入内容。重新绑定输入框或切换输入模式会清除未提交拼音，以免候选落入另一输入框。密码模式使用适合密码的输入限制，并关闭中文和语音。应用收到 READY/CANCEL 后自行决定提交表单或隐藏键盘，不能把隐藏动作实现成清空正文。

笔记编辑只更新变化的内容块，空闲时由后台保存。键盘事件不应为一次换行重新编码整篇笔记。键盘 API、事件和尺寸处理见[界面与输入](../development/touch-ui.md)。

## 锁屏、弹框与通知

锁屏保留原应用状态，限制普通页面导航和系统弹框。TF 卡加载等请求在锁屏期间延后，解锁后先确认请求仍有效，再使用统一系统弹框显示。通知可保留在通知中心；提醒到达不应在锁屏上打开普通业务页面。

休眠期间仅运行明确请求的维护步骤，用于保存、取消、释放和恢复，不刷新普通业务页面。唤醒按压由系统消费，避免同一次按键继续触发页面动作。

## 定位交互迟缓

先区分输入未分发、业务同步等待、后台结果未完成与显示正在刷新。记录事件受理、后台完成、帧提交和显示完成的时间点；检查界面线程是否等待公共存储锁或跨核响应，以及页面恢复是否执行重复扫描。阅读数据流及各阶段的职责见[阅读与双核计算](reading-architecture.md)。
