# 阅读与双核计算

阅读器把文档解析、文字排版、字形生成和页面像素合成交给 ACPU。HCPU 保存文件句柄、管理缓存、接收用户操作并提交显示。两个核通过项目已有的计算组件框架协作，ACPU 不直接操作文件系统和 LVGL 页面。

## 从点击书籍到显示正文

| 顺序 | 执行位置 | 输入与处理 | 输出及等待条件 |
| --- | --- | --- | --- |
| 1. 接受打开请求 | HCPU 界面线程 | 取得书籍路径、文件版本、上次阅读位置和全局排版设置，创建阅读页面。 | 页面保留加载状态；文件读取和跨核调用交给后台。 |
| 2. 定位内容 | HCPU 文档后台与 ACPU 文档组件 | EPUB 选择正文文件及章节内位置；TXT 根据源字节位置选取前文与后续窗口。 | 有效缓存可以直接供数；缓存未命中时启动转换。 |
| 3. 转换文档 | ACPU 文档组件；HCPU 响应资源请求 | ACPU 解压、解析标记、提取正文、标题、链接、注释与图片。缺少文件字节时暂停算法，HCPU 分段读取后继续原上下文。 | 按记录输出正文与源位置。正文、导航和持久化收尾各有完成状态。 |
| 4. 取得字体 | HCPU 字体来源管理与 ACPU 字体组件 | HCPU 提供全局字体身份及来源。ACPU 测量字符并生成字形位图。内置 FTZ 可直接使用只读映射；外置字体按需请求字节。 | 测量结果用于断行，位图用于合成；二者分别缓存。 |
| 5. 排版 | HCPU `rdview` 工作线程调度 ACPU 排版组件 | 结合正文、字符宽度、字号、行距和页面尺寸推进排版。 | 生成页面边界、行和字符位置；当前页优先发布。 |
| 6. 合成页面 | HCPU `rdview` 调度 ACPU 页面合成组件 | 把字形、图片和标题装饰合成为页面帧。 | FINISH 成功后，帧才具备可显示的完整像素。 |
| 7. 显示 | HCPU 界面、LVGL 与屏幕驱动 | 界面绑定已完成的页面帧，刷新协调器提交变化区域或全屏刷新。 | 显示完成通知解除旧帧的显示引用；墨水屏实际刷新另计耗时。 |

文档后台与 `rdview` 是不同的工作环节。`rdview` 当前使用 12 KiB PSRAM 栈，优先级为 `RT_THREAD_PRIORITY_MIDDLE + 2`。界面线程只提交意图、读取结果和更新对象，不同步等待整章排版。具体入口见 源码：`modules/common/reader/reader_view.c` 和文档组件（源码：`modules/books/compute/`）。

## 位置、章节与恢复

| 格式 | 保存的位置 | 无现成分页缓存时的恢复 |
| --- | --- | --- |
| EPUB | 正文文件序号、规范化正文的 UTF-8 字节偏移及必要的补充偏移。 | 定位目标正文文件，在该文件内恢复样式与锚点，再输出目标附近内容；不要求先排完前面所有章节。已知入口可复用章节入口缓存。 |
| TXT | 原文件字节位置和解码后的补充偏移。 | 在有限前文范围内寻找可解码边界，再从目标窗口解码和排版。UTF-8、UTF-16、GBK 的字符边界分别处理。 |
| Markdown、MOBI | 转换后的正文记录及阅读位置。 | 使用已有转换缓存；当前未实现与 EPUB 相同的任意 MOBI 章节独立转换，冷打开仍可能需要更多转换工作。 |

页码依赖字体和版式，稳定阅读位置依赖源内容。字号改变后，阅读器按源位置找到新页面，不把旧页码直接当作新版式的页面编号。章节导航和正文锚点分别维护；完整目录未到达时，页眉可以使用当前正文中已取得的标题。

EPUB 转换保留章节、标题与注释语义。章节从新页开始，标题使用独立字号、间距和左侧竖线。注释在点击后按需读取，弹框关闭时取消读取并释放结果。没有有效注释目标时显示读取失败状态，不把链接文本当作注释正文。

## 当前章、邻章与近页缓存

阅读会话保留当前章及相邻章节的文档和排版状态。当前短章节窗口最多保留七个章节上下文，ACPU 排版同时最多保留四个计算槽；超过槽数的章节可保留已生成结果，计算上下文按需要轮换。七章是有界窗口上限，实际使用仍受内存、章节长度和预取需求约束。在当前页能够显示后，后台继续推进排版，并优先准备当前页附近的字形和完整页面；后退方向也保留近页。排完整章与生成整章所有像素是两件事，后者受页面帧预算约束。

当前页、距离近的页面和反向近页优先于远页；邻章预备不能挤掉当前章仍有用的近页帧。连续翻页时，若文档、字体和版式版本相同，仍处于近页范围的计算会继续执行，避免反复取消和重做。正在显示的帧只能在显示引用解除后回收。

| 缓存或预算 | 当前上限 | 有效性与回收 |
| --- | --- | --- |
| 行与页面排版数据 | 共享 2 MiB | 受文档及版式版本约束，按实际页面距离回收。 |
| 解码图片 | 共享 2 MiB | 当前合成引用期间保留；内存紧张时停止可选预备。 |
| 页面帧 | 共享 6 MiB | 保护当前显示和近页，释放窗口外且无人引用的帧。 |
| 分页索引 | 每份最多 512 KiB，共享最多三份额度 | 记录正文位置和版式，变化时失效。 |
| 应用可用内存余量 | 缓存准入保留 1 MiB | 各缓存上限不是同时预分配的保证；实际还受应用堆剩余量限制。 |

缓存预算和章节窗口定义在 源码：`modules/common/reader/reader_view.c`，四个排版槽定义在 源码：`modules/common/reader/compute/include/reader_wire.h`。全局内存回收见[内存与存储](memory-storage.md)。章节入口缓存、正文缓存和字体缓存各有独立身份；不能仅用书名或页码判断命中。

## 字体切换与即时重排

全局字体服务保存用户选择和字体版本，书籍记录保存阅读位置。进入阅读和字体服务完成挂载扫描时均会恢复有效选择。切换书籍、退出再进入时重新绑定当前选择，不沿用前一本书的旧字体对象。

字号、字体、行距或边距变化时，界面立即提交新排版版本。后台按最近一次设置重排，菜单保持打开也会发布新正文。原页面在新帧完成前保留，避免显示半成品。连续修改期间，旧实例等待释放造成的暂时名额不足会进入等待状态；真实文件、内存或解析失败则报告错误。

“立即更改”表示设置立即进入重排并在结果可用时替换正文，实际字形计算和墨水屏刷新仍需要时间。当前实例名额为 24，名额等待不等于字体加载失败。

## 跨核会话与资源释放

组件通过 OPEN 建立远端状态，STEP 推进有限工作，CLOSE 结束会话。组件需要文件数据时，通过资源通道请求 HCPU 读取；通道传递固定宽度描述和共享缓冲，不传递 HCPU 文件对象或 LVGL 对象。

| 对象 | 持有者 | 可以释放的时机 |
| --- | --- | --- |
| 文件句柄、字体来源引用 | HCPU 文档或字体客户端 | 在途资源读取结束、对应远端会话关闭之后。 |
| 解析器与协作执行栈 | ACPU 组件 | 转换结束或取消后，经 CLOSE 正常清理。 |
| 共享控制区与输入暂存区 | HCPU 组件客户端 | CLOSE 成功且取消调用者不再访问后。 |
| 页面像素 | HCPU 阅读视图 | 合成会话已结束借用，且界面与显示链路均不再引用后。 |
| 书籍共享目录 | 同书籍版本的多个文档共同引用 | 最后一个文档释放后；局部标题锚点仍属于各自文档。 |

取消先撤销排队等待或唤醒当前任务，再由任务所有者收尾。关闭失败时保留句柄和缓冲，后续继续清理；不能因超时就释放 ACPU 可能仍在访问的地址。当前阅读链路没有完整的 HCPU 自动回退路径，远端不可用时应报告失败。

休眠前停止接收新计算并等待在途任务让出，确认计算传输已停驻后才允许 SDK 深睡眠。恢复时先恢复运行环境，再放开计算调度；详见[电源状态与恢复](power-architecture.md)。

## 响应目标与调度优先级

打开书籍的目标是点击后五秒内显示上次阅读页面。当前页准备优先于远页排版、完整目录和持久化收尾，正文可用后持续准备邻近页面。

打开五秒后，近页翻页的数据准备目标为一秒以内；打开十秒后的正常阅读及突发翻页优先直接使用已完成的页面帧。跨多章或从目录远距离跳转时，数据准备目标为三秒以内。这些数据准备时间不包含墨水屏推送和物理刷新时间。

内置和外置字体使用同一调度目标，实际耗时受书籍内容、字体和缓存状态影响。后台分别维护正文到达、排版完成、字形准备和页面帧完成状态，只有完整页面帧才可提交显示。

组件协议与算法细节分别见文档转换（源码：`modules/books/compute/README.md`）、字体计算（源码：`components/compute_reader_font/README.md`）、页面合成（源码：`components/compute_reader_render/README.md`）和阅读数据组件（源码：`components/compute_reading_data/README.md`）。
