# 电源与恢复

平台电源协调器负责让应用、计算、存储和外设在进入休眠前停止不适合继续运行的工作。SDK 负责底层时钟、芯片睡眠和蓝牙低功耗调度。锁屏仅限制交互，墙纸系统休眠需要完成资源交接，两者不是同一状态。

## 状态与转移

| 状态 | 平台正在做什么 | 后续条件 |
| --- | --- | --- |
| ACTIVE | 正常界面与服务运行；可处于桌面、阅读或锁屏。 | 锁屏后的休眠计时到达，且无活动、存储切换或阻塞任务时请求准备。 |
| PREPARING | 关闭闲置网页连接，暂停电池、校时和无线业务，协调服务保存与计算让出。 | 独立准备结果都成功后请求墙纸。 |
| DRAWING | 创建墙纸并请求全刷。 | 观察到新的显示提交后进入排空。 |
| DRAINING | 等待显示完成、外设和计算传输安全停驻。 | 最后一次检查活动与按键，再提交休眠。 |
| ASLEEP | 保留页面和业务内存，暂停普通绘制，由 SDK 执行允许的睡眠。 | 电源键等有效唤醒事件进入恢复。 |
| RESUMING | 恢复板级运行环境、计算调度和各服务，撤掉墙纸。 | 恢复协调完成后回到 ACTIVE。 |

准备阶段出现新活动、失败或超过 60 秒会取消休眠并恢复已暂停的服务。失败后暂停自动反复准备，由电源策略根据新的活动和计时恢复条件决定后续动作，避免无人操作时在睡眠与恢复之间循环。

状态机见 源码：`src/ui/platform/epd_power.c`，计时和失败策略见 源码：`src/ui/platform/epd_power_policy.c`。

## 子系统准备与恢复

| 子系统 | 准备完成的依据 | 唤醒后的动作 |
| --- | --- | --- |
| 应用服务 | 活动保持已释放，保存和停止维护步骤结束。 | 发送恢复事件，按原任务状态继续。 |
| ACPU 计算 | 不再准入新请求，在途工作已让出，传输确认 parked。 | 恢复 dispatch，保留会话按协议继续；中途关闭的会话重新创建。 |
| 存储 | 没有所有权切换或待释放卡资源。 | 根据当前挂载和新会话恢复访问；旧会话不复用。 |
| 屏幕与前光 | 墙纸全刷完成，显示链路空闲，前光已挂起。 | 恢复显示运行环境，撤销墙纸，再按前光偏好处理唤醒。 |
| 触摸 | 驱动完成休眠处理并给出结果。 | 重新上电或恢复控制器、中断与扫描，记录失败结果。 |
| WLAN | 连接与扫描停止，驱动退出，SDIO/IRQ/DMA 交接成功，时钟及模块使能按板级逻辑关闭。 | 重新初始化并按原开关和自动连接设置恢复。 |
| 蓝牙 | 平台发起停止扫描、断链和关闭，等待相应 SDK 结果；其他使用者占有活动时不能误报空闲。 | 按原开关恢复控制状态，协议栈内部睡眠继续由 SDK 管理。 |
| 电池 | 在途采样结束，轮询暂停，自有 ADC 引用释放。 | 更新一次状态并恢复正常轮询。 |
| 网络校时 | 在途请求完成或取消，任务停驻。 | 恢复任务，网络可用且自动校时开启时按原策略运行。 |
| USB 读卡器 | 工作期间持有运行约束，因此不满足普通休眠准入。 | 关闭读卡器后释放约束，恢复正常省电。 |

停止蓝牙扫描和连接的确认属于平台准入指标；平台不自行操纵 SDK 蓝牙核的每个调度状态。WLAN 的“已断开网络”也不等于完成驱动、总线和电源交接，需要以完整 suspend 结果判断。

## SDK 空闲睡眠与墙纸休眠

RT-Thread 没有可运行任务时，SDK 可以进入当前约束允许的空闲或浅睡眠。这个动作可能发生在未锁屏的界面状态。墙纸休眠是更高层的用户状态，需要上述准备流程。

活动中的 USB、显示、音频或计算必须持有相应电源约束，防止 SDK 在外设仍工作时关闭所需资源。设备是否显示桌面不能替代这些约束。

## 唤醒和失败边界

恢复先使运行环境可用，在保持中断开启的情况下完成可能等待总线的板级恢复，再恢复计算、字体来源及独立服务。触摸恢复失败不会跳过电池、网络等独立服务的恢复；平台保留故障结果并限制继续自动休眠。

电源协调器记录的是当次恢复结果。已记录一次长休眠后驱动处于 `TOUCH_FAULT`、而协调器结果仍显示成功的现场。手工重新初始化恢复了该现场的触摸，但长休眠故障的根因和永久修复尚未确认，详见[问题排查记录](../troubleshooting/troubleshooting.md#长休眠后触摸失效与串口丢字符)。

## 关机

关机先协调业务保存和外设停止，再显示墙纸并等待全刷，最后进入板级关机。失败时恢复已暂停的资源。再次开机从持久化记录恢复，未保存的 RAM 状态不跨关机保留。

应用接入接口和 flush 约束见[电源管理开发指南](../services/power-management.md)。日志定位应同时记录状态机阶段、各服务结果和显示完成状态，避免仅凭墙纸画面判断芯片已经睡下。
