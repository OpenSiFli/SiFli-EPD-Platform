## 按现象定位

| 现象 | 优先检查 | 对应实现或文档 |
| --- | --- | --- |
| 只显示书名或一直准备文档 | 正文供数、目标章节、计算任务状态、字体来源、文件会话。 | [阅读架构](../architecture/reading-architecture.md)；`reader_view.c`、`reader_document`。 |
| 翻页或菜单慢 | 请求受理、存储等待、字形命中、页面帧完成和显示完成分开计时。 | [显示与输入](../architecture/display-input.md)、[阅读架构](../architecture/reading-architecture.md)。 |
| 卡住且串口无输出 | 先区分串口被占用、丢字符与系统停止调度，再用对应 ELF 解释现场。 | [故障取证](dynamic-app-debugging.md)。 |
| 无法进入系统休眠 | 查询活动保持、保存、存储切换、无线准备、显示和计算 parked。 | [电源架构](../architecture/power-architecture.md)。 |
| 联网应用失败 | 本地地址和路由、DNS、连接、TLS、服务凭据分别确认。 | [网络与音频](../architecture/network-audio.md)。 |
| 安装或字体导入停住 | 存储会话、锁等待、在途任务、读写结果及校验阶段。 | [内存与存储](../architecture/memory-storage.md)。 |

## 已采用的方法

### P01 阅读过程中死机且串口无响应

| 项目 | 内容 |
| --- | --- |
| 排查与依据 | 不复位设备，通过 UART-DAP 读取当前寄存器和片内 SRAM，再使用本次运行对应的 ELF 还原调用栈。现场显示 HCPU 在保存阅读进度时等待内部 Flash 写入完成，中断已经关闭；同时 ACPU 字体任务尚未结束。本次启动的深睡计数为 0。 |
| 最终处理 | 项目计算调用层复用 SDK 的 Flash 互斥锁。启动和执行 ACPU 任务前取得锁，确认 ACPU 已进入 SRAM 等待区后才释放锁，避免计算核访问与内部 Flash 写入重叠。每个计算步骤独立持锁，不修改 SDK 通用代码。 |
| 验证与限制 | 启动、写入互斥、任务完成通知、序号变化和等待恢复等 18 项主机回归通过。第 73 版真机休眠约 10 分钟后，用户确认正文、触摸和手势翻页恢复正常；随后自动退出并重新打开《活着》两次，分别用时 3.10 秒和 2.97 秒，串口持续响应。更长时间休眠的偶发故障仍需持续观察。 |

### P02 翻页后保存阅读进度触发总线异常

| 项目 | 内容 |
| --- | --- |
| 排查与依据 | 保留现场，通过 UART-DAP 导出寄存器、片内 SRAM 和 PSRAM，使用本次固件 ELF 与保存的异常帧还原调用链。异常发生在阅读进度文件替换过程中：`storage_file_replace → rename → lfs_dir_compact → rt_flash_read`。读取地址 `0x12ea0140` 有效，但 Flash 句柄返回 `0x54c9630c`，预期为 `0x2000fa60`。相关 SRAM 指令与 ELF 完全一致，线程栈底仍有空余。 |
| 最终处理 | 在项目链接脚本中，将包括 Flash 地址查询在内、运行时必须保留在片内内存的完整代码段移到 RAM1，并同步调整启动复制、清零范围和堆起点。保留代码段中的函数和常量，不修改 SDK 通用代码，不增加运行时重复校验。 |
| 验证与限制 | 第 84 版在 ACPU 阅读并发下，原地址查询函数和原句柄查询函数各连续运行一亿次，均返回正确结果；两轮分别包含 86 次翻页。原 RAM0 布局可以复现错误返回，而 RAM1 布局在本轮检查中未复现。第 86 版实际休眠约五分钟后，用户唤醒并解锁，自动打开和重开《四世同堂》分别为 3.73、3.48 秒，十次翻页全部命中图像缓存。当前证据支持采用该布局，尚未证明底层触发原因，也不能代替更长时间休眠后的稳定性验证。最终固件移除临时压力测试代码。 |

### P06 书架仅显示文件名和默认封面

| 项目 | 内容 |
| --- | --- |
| 排查与依据 | 检查 EPUB 元数据、封面资源引用和书架显示流程，覆盖 EPUB 2、EPUB 3、封面页面及 SVG 引用。 |
| 最终处理 | 后台读取当前列表页的书名和封面，阅读请求优先。缩略图限制为 112×146 像素，最多保留四本，离开列表后取消提取。缺少有效元数据时继续显示文件名和默认封面。 大型合集的 OPF 超过原 512 KiB 大小上限时，元数据入口曾直接拒绝解析。现在复用 4 KiB SAX 分段解析，先提取标题，再查找封面；每次最多处理 512 KiB 解压 XML，只保留两个封面候选，不建立整本资源清单。提前找到信息即结束；超出范围时保留已取得的标题并回退默认封面。 |
| 验证与限制 | 真实 69 册合集成功提取标题和封面，与原实现处理等价精简包的输出一致，解析峰值约 545 KiB，未扩大 1 MiB 预算。12 组输出对照、35 项管道检查及三项解析中取消检查通过。第 74 版真机查询确认《活着》《三体》和东野圭吾合集的书架标签与提取书名一致，封面控件已绑定实际缩略图，尺寸为 109×146 像素。此项检查针对控件绑定，未使用屏幕照片作视觉比对。 |

### P07 外置字体打开和翻页缓慢

| 项目 | 内容 |
| --- | --- |
| 排查与依据 | 使用 TF 卡 Download 中的霞鹜文楷，按同一次请求分别记录正文供给、排版、字形准备、文件读取、存储锁等待和屏幕刷新耗时，以页面图像实际完成时间判定预备命中。 |
| 最终处理 | 外置字体在两端使用 4 KiB 对齐块缓存，在原容量内优先保留字符映射、字宽和字形位置等字体表，至少留八块供字形轮廓读取。HCPU 同一来源的不同字号共享缓存，每来源最多 256 KiB、总计 512 KiB；后台最多保留两个 TF 字体文件句柄。ACPU 外置字体缓存为 256 KiB，计入单会话 704 KiB 上限，内置压缩字体缓存为 16 KiB。字体计算组件采用速度优化编译。 字体来源和文件句柄复用已确认的路径版本；版本变化时重新检查，读取前后仍核对租约、挂载和存储交接，实际读取持有存储锁。取消、拔卡或字体失效后由后台释放句柄；睡眠保护覆盖字形任务和管道关闭，清醒时省去重复的后台通知。 排版按 64 个字符准备字形，保留英文词尾前瞻和段落边界；当前页及近页优先于远页和整章统计。三张前向页面图像完成后，利用原临时区预排第四页，不新增第四张图像；每个位置的可选预排最多两秒，新请求优先。 |
| 验证与限制 | 已有样本覆盖霞鹜文楷下的 EPUB、TXT 打开及连续、反向翻页。结果依赖书籍内容、目标位置和缓存状态，尚不能据此认定所有书籍和字体均达到相同性能。 |

### P08 跨核排版批次重复复制未使用区域

| 项目 | 内容 |
| --- | --- |
| 排查与依据 | 对照客户端、传输解码和远端执行的批次交接，发现每次都复制约 47 KiB 的完整结构，一次交接经过三处复制，包含大量未使用的文本、字形和排版条目。 |
| 最终处理 | 使用统一的有界复制函数，仅复制当前批次的头部、有效排版条目、文本和字形槽位。保留有效范围内表示“尚未测量”的零值，不增加堆分配，不改变跨核协议。 |
| 验证与限制 | 43 项 ASan 回归及两项故障对照通过，覆盖真实客户端、传输、远端执行和未使用尾部数据；既有 41 项计算回归通过。Cortex-M33 相关代码增加 152 字节，没有新增常驻缓冲。 |

### P09 文档收尾写入占用近页准备时间

| 项目 | 内容 |
| --- | --- |
| 排查与依据 | 对照翻页请求和文档收尾日志，发现索引、元数据和缓存提交仍在近页字形准备期间执行，占用公共存储锁。 |
| 最终处理 | 文档内容关闭完成后立即发布可读的结束状态，缓存元数据和索引保存独立执行。当前页及近页排版、图像准备期间暂停可选写入和其他章节的推测读取；缺少正文时通过明确的数据请求推进转换。三页准备完成或遇到缓存容量限制后恢复后台处理。切换章节后，解析目标前由新章节接管读取调度；调度对象变化时唤醒文档线程，即使预读开关值没有变化。 |
| 验证与限制 | 21 项收尾、11 项分页、4 项近页调度、23 组异步视图及文件句柄集成通过 ASan。新增三项回归覆盖保留旧显示页切章、后台计数后切章和相同开关值下调度对象变化，修正前均可复现等待，修正后通过。最新真机结果见外置字体问题，连续翻页仍有未完整命中的情况。 |

### P10 邻章准备停在已转换正文末尾

| 项目 | 内容 |
| --- | --- |
| 排查与依据 | 对照邻章开始准备、正文可用位置和翻页请求，使用实际分页及文档供数流程重放。原流程在正文末尾停住，后续 128 次调度没有继续转换；用户切入后才补做字形和页面图像。 |
| 最终处理 | 获准准备的邻章当前页及近页可以请求必要正文，计算仍使用后台优先级。先完成阅读方向的邻章页面，再开始反向章节，避免反向读取提前接管转换。记录页面图像真正完成的时间，只有在翻页请求前完成才报告 `prepared=1`。 连续短章节按实际前后三页扩大预备范围，最多保留七个章节上下文；扩展上下文计入原 2 MiB 排版预算，页面图像保持 6 MiB 上限及 1 MiB 平台余量。跨章时直接接管已准备的页面和完成时间，内存不足时回收更远的可选页面。 计算任务保持四个对象上限，章节之间直接转移空闲对象；扩展窗口完成或移出预备范围后，独立取消遗留任务及读取请求，保留显示页与完整图像。索引扩容按实际增量计费，反向裁剪页通过正文结束游标判断章节边界。 直接相邻章节也参与全局窗口调度，入口图像被取消后会重新准备。其他章节仍在转换时暂缓新建可选转换，并恢复已有转换的供数，避免前后章节互相取消或停在等待结束状态。近页日志分别记录正文、字形、排版等待和图像准备、接管、取消。 |
| 验证与限制 | 最终生产源码的 24 组异步视图、17 项图像接管及全局窗口回归通过 ASan，覆盖连续三个单页章节、实际反向裁剪、四任务占满后回收、内存不足、跨章接管、休眠取消及延迟释放。清理后任务、文件和分配计数归零；七项负面对照分别捕获窗口缺失、任务未转移、末页未识别、任务未回收、邻章入口缺失、转换被抢占和供数未恢复。真机复测待完成。 |

### P11 阅读线程占用片内内存

| 项目 | 内容 |
| --- | --- |
| 排查与依据 | 第 72 版外置字体阅读时，片内堆空闲约 13 KiB，而阅读线程栈单独占用 12 KiB；应用 PSRAM 仍有约 1.36 MiB 空闲。 |
| 最终处理 | 使用平台已有的 PSRAM 线程创建接口存放阅读线程栈，保留原栈大小、优先级和退出释放流程，线程控制结构仍留在片内内存。 |
| 验证与限制 | ARM 编译及线程退出、取消回归通过。第 74 版完成多本 EPUB 与 TXT 连续阅读后，阅读线程栈位于 PSRAM，实测使用约 29%；应用 PSRAM 仍有 1,259,968 字节空闲，LVGL 独立内存池有 1,757,812 字节空闲。 |

### P12 大型 EPUB 冷打开的 ZIP 校验耗时

| 项目 | 内容 |

## 长休眠后触摸失效与串口丢字符

2026-11-02 的现场确认系统调度和电池监测仍运行。触摸驱动处于 `TOUCH_FAULT`，恢复计数为三次，错误为 -1，中断关闭；电源协调器已回到活动状态，仍保存触摸恢复成功结果。该差异说明需要检查驱动故障发生时刻，不能仅靠协调器状态判断触摸正常。

COM18 在 1 Mbps 下整行发送命令只收到首字符，逐字发送可以执行；临时禁止睡眠后，同样的整行命令可以执行。现场通过临时保持运行并重新上电初始化触摸恢复了操作，用户确认解锁、点击和滑动正常。

触摸三次恢复失败的具体步骤、串口低功耗切换时丢字符的环节仍未确定。I2C 总线复位会清除错误码，事后零错误码不能证明此前读取成功。现场恢复是处理措施，尚未证明长休眠问题已永久修复。后续复现应保留启动起点、睡眠和恢复阶段日志、触摸错误及串口发送方式；使用与镜像配套的 ELF 解释寄存器和线程。
