# 参与开发

提交问题时说明固件及应用版本、使用的板型、可重复的操作步骤、预期结果和实际结果。构建问题附执行命令及第一处错误；运行问题附相关串口日志。动态应用异常的采集方法见[故障取证](../troubleshooting/dynamic-app-debugging.md)。

## 修改与验证

应用功能在对应 `modules/<id>/` 中修改；共享应用组件位于 `modules/common/`；常驻平台、板级适配和构建工具的位置见[平台架构](../architecture/architecture.md)。使用仓库记录的 SDK 子模块，准备环境见[首次运行](../getting-started/getting-started.md)。

一个修改围绕具体问题组织。涉及公共接口时同步调用方、导出和文档；涉及文本时更新相应 `i18n` 输入，由构建生成翻译资源。应用资源与源码放在所属应用目录，入口见[图像与字体](../development/application-resources.md)。

完成修改涉及的功能验证和原生构建。提交说明写清问题、修改后的行为、验证命令和结果。真机操作与主机测试分别记录；尚未执行的硬件验证说明原因和所需条件。

临时串口插桩、测试账号、私有密钥和本机绝对路径不属于发布源码。构建产物保留在既定输出位置；发布所需的固件、应用包和配套符号按[构建说明](../build/building.md)留存。
