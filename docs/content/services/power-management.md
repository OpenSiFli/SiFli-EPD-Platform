# 电源管理

系统将界面锁屏、显示墙纸后的系统休眠和关机分别处理。应用使用受管服务声明持续工作及保存状态；电源状态机位于 `src/ui/platform/epd_power.c`，硬件交接位于 `src/boards/board_pm.c` 和 `board_service.c`。

## 状态与输入

锁屏保留当前应用和页面，屏蔽普通导航。KEY1 短按进入锁屏，长按三秒打开电源菜单；锁屏时短按按用户前光偏好临时点亮三秒。锁屏控件持续按住一秒后解锁。

墙纸系统休眠保留页面、模块和业务内存，暂停普通 LVGL 定时处理。实体键唤醒的整次按压只恢复锁屏，不继续分发给应用或触发长按菜单。唤醒后存活 worker 通过原有 `EPD_SERVICE_WAKE` 事件继续工作。

关机协调保存和资源关闭，之后进入板级关机流程。重新开机从持久化记录重建应用；内存中的朗读缓存或未保存的页面对象不跨关机恢复。

## 持续任务的休眠锁

`src/services/app_service.h` 提供：

```c
bool epd_service_sleep_acquire(epd_service_t *service);
void epd_service_sleep_release(epd_service_t *service);
```

服务在接受下载、播放、生成或保存任务前申请，成功后才入队。返回 `false` 表示服务正在停止或系统已经提交休眠；应用保留待处理意图，恢复后再尝试。

同一服务重复申请是幂等操作。服务内部存在多个任务时，服务汇总活动，在最后一个任务及资源收尾结束后释放。平台停止服务时等待 worker、在途调用和 UI 清理完成再移除持有状态。

该锁阻止墙纸系统休眠，不阻止锁屏。设备正在使用 DMA、总线或音频时，由驱动持有相应 SDK 电源约束。

## 保存与维护步骤

受管描述符的 `flush()` 在 UI 线程执行，只提交取消和保存请求，不能阻塞等待 worker。返回 `false` 表示未保存完成或保存失败；只有业务记录已经提交后才返回 `true`。

系统休眠期间仍在原 UI 线程处理服务停止、存储释放和 `epd_service_ui_request()` 明确申请的维护步骤，保持墙纸，不提交普通页面绘制。应用的维护回调必须限制单次工作量。

TF 卡或 USB 所有权交接沿用存储会话及保存协议。旧卡会话失效后，旧任务不能向新卡提交数据。见[应用生命周期](../development/application-lifecycle.md)。

## 外设准入

普通锁屏保留外设服务。显示墙纸并进入系统休眠时，平台按以下顺序交接；关机也等待这些服务停止后才进入 Hibernate。

1. 暂停电池轮询和网络校时，等待在途采样、DNS 和 UDP 请求结束。电池服务释放自己的 ADC 引用，充电硬件继续独立工作。
2. 停止 WLAN 连接、蓝牙扫描和重连。WLAN 驱动关闭并确认 SDIO、IRQ、DMA 空闲后，停止卡时钟并拉低模块使能脚；蓝牙等待断链、SDK 关闭确认和扫描关闭确认。
3. 显示墙纸并完成全刷，确认前光关闭；触摸控制器进入停止扫描的休眠模式，随后允许 SDK DEEP。

各服务的 `suspend()` 提交请求，`suspend_result()` 返回 `-RT_EBUSY` 表示仍在收尾，返回 `RT_EOK` 才表示准备完成。失败、中途唤醒或准备超过 60 秒时取消休眠。同步 DNS 未返回时仍保留休眠锁，不强行删除线程。正在播放的蓝牙音频或由其他服务拥有的 BLE 活动会阻止本轮休眠。

唤醒先恢复 SDK 运行约束和触摸控制器，再恢复网络服务、电池轮询及校时。WLAN 重新上电、初始化并尝试恢复休眠前的连接；蓝牙按原开关和连接目标恢复。电池立即更新一次状态和电压，网络校时等待网络就绪。整个过程不改写用户的开关、自动连接和自动校时设置；触摸恢复结果单独记录，失败不再跳过网络、电池和校时等独立服务的恢复；电源策略保留故障状态并限制下一次自动休眠。长睡眠触摸异常的未确认原因见[问题记录](../troubleshooting/troubleshooting.md)，完整状态顺序见[电源与恢复](../architecture/power-architecture.md)。

热点开启时保持系统运行。关机由网页热点服务先停止热点；若关机失败，服务恢复原热点请求并复用当次名称和密码。关机的触摸断电操作持有驱动锁，返回时先恢复供电，再重新配置控制器和中断。

进入 SDK DEEP 要求显示完成、后台休眠锁全部释放，并且外设交接成功。具体 WLAN 条件见[网络服务](wifi.md)。

动态锁屏的声明与解锁入口见[应用界面](../development/touch-ui.md#动态锁屏)。关机和唤醒由平台协调，普通应用通过受管服务参与保存和恢复。
