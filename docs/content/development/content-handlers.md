# 文件内容交接

文件管理器根据已安装应用的 `app.json` 发现文件处理者。点击普通文件时，一个处理者会直接打开文件；多个处理者会显示可翻页的应用选择列表；没有处理者时继续显示文件名和大小。

## 声明支持的文件

应用源码清单 `app.json` 通过 `file_extensions` 声明文件类型。下面只展示该字段，以书架支持的格式为例；合并到应用已有清单中，其余字段沿用该应用的实际配置：

```json
{
  "file_extensions": ["txt", "md", "markdown", "epub", "mobi"]
}
```

扩展名使用不带点的小写 ASCII 字母或数字。数组中的元素必须是非空字符串，不能重复。字段可以省略，也可以是空数组。资源包不能声明非空处理者列表。扩展名数量和字符串长度不设额外固定上限，仍受实际 manifest 读取和内存分配结果约束。

`tools/package_app.py` 校验并将字段复制到安装包；设备端包校验和元数据读取执行相同的格式检查。平台匹配最后一个路径分量的最后一个扩展名，忽略扩展名的 ASCII 大小写。只含扩展名的隐藏文件（例如 `.txt`）不匹配。

书架的完整声明见 源码：`modules/books/app.json`，其 `background` 为 `false`，阅读任务在使用时启动。图库声明 PNG、JPG、JPEG。文件类型声明表示应用接受该格式的打开请求，具体文件是否能够解码由应用判断。

## 平台接口

应用包含 `platform/app_content.h`，公开声明位于 `src/ui/platform/app_content.h`。接口在 UI 线程使用。

| 接口 | 行为 |
| --- | --- |
| `app_content_query(path, first, items, capacity, count)` | 检查文件并分页复制处理者 ID 和名称；`count` 返回全部匹配数量。 |
| `app_content_open(id, path)` | 重新检查安装位置、处理者声明、文件和恢复模式，随后将 intent 交给 `app_fwk`。 |
| `app_content_receive(intent, path, size)` | 将传入路径完整复制到应用提供的缓冲区，并验证文件和 TF 卡会话；普通启动返回 `-ENOENT`。 |
| `app_content_error(error)` | 返回可供界面显示的错误文字。 |

处理者发现只读取 catalog 和安装 manifest，不加载应用 ELF。选择列表持有字符串副本，catalog 刷新不会使界面保存的对象失效。实际打开时会再次确认处理者可用性。`app_content_open()` 返回 `RT_EOK` 表示消息已入队；模块加载和应用入口在框架后续调度时执行。

## Intent 和路径容量

平台仅将应用 ID 传给 `intent_init()`，完整文件路径由 `intent_set_string(intent, "path", path)` 写入。路径中的 UTF-8 中文、空格和等号会原样传递。平台不会将路径拼接为命令行，也不会截断后继续打开。

本地 SDK 的 `intent_int.h` 定义 `INTENT_MAX_LEN = 128`。`intent.c` 的追加规则要求累计使用字节数严格小于 128。总用量包括应用 ID 及其结束符、`path=` 和完整路径及结束符、请求序号 `r=`，以及 TF 路径的卡会话 `s=`。中文按 UTF-8 字节计数，序号和会话按实际十六进制字符串计数，因此不能用单一字符数表示所有路径的可用长度。

平台检查每次 `intent_set_string()` 的实际返回值。容量不足返回 `-ENAMETOOLONG`，分配失败返回 `-RT_ENOMEM`，均不会发送不完整请求。接收缓冲区不足同样拒绝复制。应用不得保存 `intent_get_string()` 返回的借用指针；`app_content_receive()` 返回的路径已经位于应用自有缓冲区。

## 已运行应用与页面生命周期

SDK 的 `app_fwk` 根据 intent 决定恢复应用或重新启动应用。平台为每次内容打开附带不同的请求序号，因此重复打开同一文件也会重新进入应用；已有页面先按框架生命周期完成 ONPAUSE、ONSTOP 和销毁。应用在入口中复制请求，在新页面就绪后处理文件。

书架在 `app_main()` 中复制请求并记录本次启动。服务的 UI 回调确认此次启动对应的书架页处于前台、且旧阅读页面已退出后，关闭旧阅读会话并打开指定文件。书架根目录之外的文件通过独立活动条目接入阅读、缓存和历史保存。实现见 源码：`modules/books/app_main.c` 的 `content_process()`。

图库在入口复制请求，待图库服务启动后通过框架创建图片页。图片页再次复制模块持有的路径，跨页面消息不携带浏览页或 intent 的借用指针。页面暂停时暂停轮询并取消请求；图片页停止时删除定时器、取消请求、等待绘制结束并释放图片；浏览页停止时停止图库服务。

## 存储和恢复模式

平台在存储锁内检查文件与安装位置。文件必须是 `/flash/` 或 `/sdcard/` 下的普通文件，路径不能包含空分量、`.` 或 `..`。TF 请求包含发起时的卡会话，接收时卡已移除或被替换会拒绝请求；应用在延后打开前也再次检查会话。图库在恢复和读取结果时检查存储会话，失效结果不会继续显示。

恢复模式下平台拒绝内容启动，catalog 的动态加载入口也在加载 ELF 前执行恢复策略。平台不会绕过该加载入口。
