# ADR-002: 内存分区策略

## 状态

已采纳

## 背景

SF32LB57 提供的 PSRAM 资源为 16 MiB，需要在 HCPU 和 ACPU 之间分配。墨水屏阅读平台的内存使用特征：

**HCPU 侧需求**：
- LVGL 界面对象和绘制缓冲
- 应用模块代码和数据
- 文件读取缓冲、网络响应
- 阅读缓存（排版结果、图片、页面帧）
- 音频播放缓冲

**ACPU 侧需求**：
- 文档解析器上下文（EPUB/MOBI 解压、HTML 解析）
- 字体解析器和字形生成工作区
- 排版引擎私有状态
- 页面合成的临时缓冲

**设计挑战**：
1. 两核内存需求不固定，随使用场景变化
2. 跨核内存访问需要显式同步，不能随意共享
3. 阅读场景下 ACPU 计算频繁，但音乐播放时 ACPU 较空闲
4. 分区过于均衡会导致某一侧资源不足

## 决策

**采用固定分区策略：**

| 区域 | 容量 | 用途 |
| --- | --- | --- |
| **HCPU PSRAM** | 13.5 MiB | 应用数据、LVGL 对象、阅读缓存、跨核共享缓冲 |
| **ACPU PSRAM** | 2.5 MiB | 算法私有上下文、计算工作区 |
| **HCPU SRAM** | ~454 KiB | 内核对象、控制结构、硬件约束的缓冲 |
| **ACPU SRAM** | 64 KiB | ACPU 固件运行数据 |

**分区依据**（来自 `project/sf32lb57-epd-gyd7n6_hcpu/ptab.json`）：
```json
{
  "mem": "psram1",
  "base": "0x60000000",
  "regions": [
    {"offset": "0x00000000", "max_size": "0x00D80000", "tags": ["PSRAM_DATA"]},
    {"offset": "0x00D80000", "max_size": "0x00280000", "tags": ["ACPU_PSRAM"]}
  ]
}
```

**关键约束**：
1. **单向分配**：`epd_app_alloc(..., EPD_APP_PSRAM)` 失败时返回空指针，不自动回退到 SRAM
2. **跨核共享缓冲由 HCPU 拥有**：ACPU 在约定的会话生命周期内借用
3. **阅读缓存预算**：排版 2 MiB、图片 2 MiB、页面帧 6 MiB（非预分配，按需使用）
4. **ACPU 组件私有预算**：文档转换最多 1 MiB、字体会话最多 704 KiB

## 理由

### 为何选择 13.5 / 2.5 MiB 分配比例

1. **HCPU 是主要内存消费者**
   - LVGL 界面和应用模块常驻
   - 阅读缓存峰值可达 10 MiB（排版 + 图片 + 页面帧）
   - 多个应用同时在后台（如音乐 + 天气）需要额外空间

2. **ACPU 计算是流式的**
   - 单个页面合成完成后释放大部分工作区
   - 多数组件私有预算在 500 KiB - 1 MiB 范围
   - 2.5 MiB 足够支持文档转换 + 字体 + 排版同时工作

3. **实测数据支撑**
   - 复杂 EPUB 文档转换峰值内存约 1 MiB
   - 字体会话（包括字形缓存）约 704 KiB
   - 页面合成的 ACPU 临时缓冲约 500 KiB
   - 预留余量应对边界情况

### 为何不采用动态分区

**考虑过但未采纳的方案**：
- HCPU 和 ACPU 共享内存池，按需分配

**未采纳原因**：
1. **缓存一致性开销**：跨核分配需要频繁的缓存同步
2. **所有权模糊**：动态分配增加释放时机判断的复杂度
3. **实时性下降**：ACPU 计算等待 HCPU 分配器会引入不确定延迟
4. **实现复杂**：需要跨核内存管理器和锁机制

固定分区虽然不能动态调整，但带来了：
- **清晰的所有权**：HCPU 分配器和 ACPU 分配器独立工作
- **可预测性**：组件私有预算明确，便于容量规划
- **简单性**：无需跨核同步的内存分配路径

## 后果

### 正面影响

1. **资源隔离清晰**
   - HCPU 应用内存不足不会影响 ACPU 计算
   - ACPU 算法内存泄漏（如果存在）不会挤占界面资源

2. **性能可预测**
   - 分配路径无锁，延迟确定
   - 组件预算明确，便于检查是否满足需求

3. **调试友好**
   - 两个独立的内存统计
   - 分区溢出问题易于定位

### 负面影响与应对

1. **不能动态平衡负载**
   - 场景：音乐播放时 ACPU 空闲，但 HCPU 可能内存紧张
   - 应对：通过内存压力协调器回收后台应用，而非依赖跨核借用

2. **阅读缓存受限于 HCPU 分区**
   - 场景：极端情况下页面帧缓存可能不足
   - 应对：缓存预算设计有优先级（当前页 > 近页 > 远页），按距离回收

3. **组件预算需要提前规划**
   - 场景：新算法接入时需要评估 ACPU 预算是否足够
   - 应对：组件清单中明确声明私有内存需求，构建时检查

## 实际内存使用示例

### 阅读复杂 EPUB（峰值情况）

| 位置 | 内存类型 | 使用项 | 大小 |
| --- | --- | --- | --- |
| HCPU | PSRAM | LVGL 对象 + 界面 | ~2 MiB |
| HCPU | PSRAM | 阅读缓存（排版 + 图片 + 帧） | ~8 MiB |
| HCPU | PSRAM | 跨核共享缓冲 | ~1 MiB |
| HCPU | PSRAM | 应用模块 + 其他 | ~1.5 MiB |
| **HCPU 小计** | | | **~12.5 MiB / 13.5 MiB** |
| ACPU | PSRAM | 文档解析上下文 | ~1 MiB |
| ACPU | PSRAM | 字体会话 | ~700 KiB |
| ACPU | PSRAM | 排版引擎 | ~300 KiB |
| ACPU | PSRAM | 页面合成工作区 | ~500 KiB |
| **ACPU 小计** | | | **~2.5 MiB / 2.5 MiB** |

### 音乐播放（ACPU 较空闲）

| 位置 | 内存类型 | 使用项 | 大小 |
| --- | --- | --- | --- |
| HCPU | PSRAM | LVGL 对象 + 界面 | ~1.5 MiB |
| HCPU | PSRAM | 音乐播放缓冲 | ~500 KiB |
| HCPU | PSRAM | 其他应用 | ~2 MiB |
| **HCPU 小计** | | | **~4 MiB / 13.5 MiB** |
| ACPU | PSRAM | 音频解码上下文 | ~300 KiB |
| **ACPU 小计** | | | **~300 KiB / 2.5 MiB** |

音乐场景下 ACPU 空闲 2.2 MiB，但这部分资源暂不跨核借用，简化实现。

## 未来演进可能

如果后续硬件升级到 32 MiB PSRAM，建议分配比例调整为：
- HCPU: 26 MiB（翻倍）
- ACPU: 6 MiB（2.5倍，支持更复杂的算法或更大的字体缓存）

保持约 4-5:1 的分配比例，符合主核为主、协处理核为辅的职责定位。
